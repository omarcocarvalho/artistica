# M5-A: Named Presets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Named presets ("A4 value studies") kept on this device, applied in one action, and exported or imported as a JSON file. A preset holds settings only: page setup, study settings and line settings. It never holds a photo, a photo's name, a content hash, a layout, or anything else derived from a photo.

**Architecture:** A pure model, `src/shared/model/preset.ts`, owns the `Preset` type, the file format, the Zod schemas, the sanitizers and the import report (A1). The settings store keeps the list (schema v5, A2), and `src/app/presets.ts` applies a preset across the settings store and the images store. The Presets dialog (A3) is the only UI. The browser's own file APIs do the export and import: a `Blob` behind an `<a download>`, and `File.text()` from a hidden `<input type="file">`. There is no network and no new dependency (M5-R1).

**Tech Stack:** TypeScript 6, Zod 4, zustand 5, React 19, existing `Dialog`, `Button`, `Callout`, i18next, Vitest 5, fast-check 4, Playwright 1.63. No new dependencies.

**Spec:** `docs/spec.md` §2.9 (presets in M5; images and anything derived from them never saved), Q34 (last settings in M1, presets later, stored in `localStorage`), §3 (privacy) **and** the overview (M5-R2–R6; Shared contracts → Presets; Privacy; questions Q1–Q4). **Design:** `design/presets.html` (added by E1; there was no mockup before M5).

## Global Constraints

As in the overview. E2E ports 65xx (A1 6501 … A4 6504). `src/shared/model/preset.ts` joins the coverage `include` (A1).

## Review Focus

1. **Nothing derived from a photo** can enter a preset or a preset file. The schema is a whitelist, and a property test builds presets while photos are loaded and checks that the serialised JSON has none of the photos' ids, names, hashes or sizes.
2. **Import is total and safe.** Any input (not JSON, a huge file, a deep nesting, a newer version, `__proto__` keys, wrong types) gives an error report or a sanitised preset. Import never throws into the UI, never fetches, and never writes a field outside the whitelist.
3. **One sanitizer per value.** Imported and stored presets go through the same `sanitizeStudy`, `sanitizeLines` and `normalizePageSetup` as saved settings. No second set of ranges.
4. **Storage writes only on change** (M3 B2 rule): saving an identical preset, or renaming to the same name, does not write `localStorage`.
5. **Apply order** (M5-R6): the preset's study versions survive `StudyDefaultsEffect` (test in A2).

### Task A1: Preset model and file format

**Branch:** `feat/presets-model` · **PR title:** `feat(settings): add the preset model and file format` · **Depends on:** —

- [ ] **Step 1: Failing tests** (`preset.test.ts`, node):
  - `presetFromSettings keeps the page setup, the study settings with versions, and the line settings without guide switches` (M5-R2: `edges.on`, `face`, `pose` are false; `edges.detailPct` is kept);
  - `a preset never carries unit, theme or language` (keys of the serialised preset are exactly `name`, `pageSetup`, `study`, `lines`);
  - `sanitizePreset clamps every value with the settings sanitizers` (table: safe area 1 → 3, bleed on with gutter 2 → gutter 6, blur 900 → 100, values 1 → 2, line width 9 → 2, colour 'red' → default);
  - `presetName trims, collapses inner whitespace, and refuses empty or longer than MAX_PRESET_NAME (40) characters` (counted in Unicode code points, so 40 emoji fit);
  - `sameName compares case-insensitively after trimming` (`'A4 values'` = `' a4 VALUES '`);
  - `uniqueName appends " (2)", " (3)" … against existing names` (`'A4'` with `['A4', 'A4 (2)']` → `'A4 (3)'`; the suffix shortens the base so the result stays ≤ 40);
  - `buildPresetFile gives { format: "artistica-presets", version: 1, presets }` and pretty-prints with 2 spaces and a final newline;
  - `parsePresetFile` reports (each its own test, `PresetImportError` kinds):
    - `too-large` for text longer than `MAX_PRESET_FILE_BYTES` (64 KiB) in UTF-8 bytes, checked before `JSON.parse`;
    - `not-json` for invalid JSON;
    - `not-presets` for valid JSON without `format: "artistica-presets"` (an Artistica settings envelope, an array, `null`);
    - `newer-version` for `version` > `PRESET_FILE_VERSION`, with the version in the report;
    - `empty` when no preset survives;
  - `parsePresetFile keeps the valid presets and counts the skipped ones` (a preset missing `name` or with a non-object `pageSetup` is skipped; a preset with a bad value inside a valid shape is sanitised, not skipped, and counted in `adjusted`);
  - `parsePresetFile drops unknown keys and ignores __proto__ and constructor keys` (the result has no own `__proto__`; `Object.prototype` is unchanged after parsing `{"__proto__": {"polluted": 1}}`);
  - `parsePresetFile reads at most MAX_PRESETS_PER_FILE (50) presets` (the rest are counted as skipped);
  - `a file from buildPresetFile parses back to equal presets` (round trip).
  `preset.property.test.ts` (fast-check):
  - `parsePresetFile never throws` for any string and any JSON value (`fc.json()`, `fc.string()`, `fc.anything()` stringified);
  - `sanitizePreset is idempotent`;
  - `no photo data leaks`: for random `ImageDescriptor`-like objects (ids, hashes, names) and random settings, `JSON.stringify(buildPresetFile([presetFromSettings(...)]))` contains none of the photos' `id`, `contentHash` or name strings.
- [ ] **Step 2: RED, implement, GREEN.** Version handling is a table, `PRESET_FILE_MIGRATIONS: Record<number, (raw) => raw>`, empty for version 1, so a later version adds one entry (M5-R4). Zod parses each preset on its own with `.catch` per field, as `settingsSchema` does, then the shared sanitizers run.
- [ ] **Step 3: Coverage.** Add `src/shared/model/preset.ts` to the coverage `include` in `vite.config.ts`.
- [ ] **Step 4: Pre-PR command (6501), PR.**
