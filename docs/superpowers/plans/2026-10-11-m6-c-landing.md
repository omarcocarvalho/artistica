# M6-C: Translated Landing Pages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pre-rendered, static landing page per language (`/artistica/` in English, `/artistica/<code>/` for the others) with `hreflang`, canonical URLs, a generated sitemap, Open Graph tags, a share image and translated FAQ structured data; English copy that describes what 1.0 does; and a privacy text that stays exact in every language.

**Architecture:** today's `index.html` becomes a template, `landing/page.html`, plus `landing/locales/en.json`. A Vite plugin, `scripts/vite-landing.ts`, renders one page per language at build and on request in dev (M6-R19), and writes `sitemap.xml` (M6-R22). `landing/main.ts` keeps only behaviour (the theme toggle), reading its labels from data attributes. C2 rewrites the English copy before the string freeze; C3, after the translations, renders the share images and checks every language end to end.

**Tech Stack:** Vite 8 plugin API, HTML, Tailwind CSS v4, Vitest 5, Playwright 1.63 with `@axe-core/playwright`. No new dependencies (M6-R1).

**Spec:** `docs/spec.md` §2.11 (landing pre-rendered; `WebApplication` and `FAQPage` data; sitemap, robots, canonical; M6 translated pages with `hreflang`, Q36) **and** the overview (M6-R2, R19–R23; questions Q3, Q7, Q9). **Design:** `design/landing.html` (footer language control at line 96; D1 turns it into a list of links).

## Global Constraints

As in the overview. E2E ports 73xx (C1 7301 … C3 7303). The landing stays static: no client-side rendering of text, every page readable with JavaScript off. The host audit must still pass (`node scripts/audit-hosts.ts dist`): the only external link stays the GitHub source link already on the allow-list.

## Review Focus

1. **Escaping:** a locale value can't inject markup into text, attributes or JSON-LD (M6-R19); only the allow-listed tags in `…Html` keys pass.
2. **SEO set per page:** canonical to itself, seven alternates plus x-default, `og:locale` and alternates, JSON-LD equal to the visible FAQ, `inLanguage` right.
3. **Links:** absolute links to the app with `?lang` on translated pages; nothing relative that breaks under `/<code>/`.
4. **Privacy claims:** the English claims match what the code does after M5 (presets, the face and pose models), each with its backing test (M6-R23).
