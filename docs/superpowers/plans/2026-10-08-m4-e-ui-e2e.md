# M4-E: UI, Shell and E2E Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The "Guides from the photo" section of the Lines panel (desktop tab and phone card), wired to the detections scheduler, the downloads, the export gate and the page description; the service worker registered; and the E2E proof of both exit criteria — offline once the models are cached, and nothing uploaded — plus the phone, memory and timing checks.

**Architecture:** `GuidesSection` reads `useImages` and `useDetections`, writes line settings through `updateLines`, and calls the scheduler's `download`/`retry` through a small context provided by the app (`DetectionsProvider`), so the feature component never creates engines. `DetectionEffect` keeps the scheduler in sync with the images. The pipeline gets `guidesFor`. E2E uses two committed photo fixtures (owner Q12) and the real models.

**Tech Stack:** React 19, Radix (existing `Switch`, `Slider`), i18next, Testing Library, Playwright 1.63 with `@axe-core/playwright`. No new dependencies.

**Spec:** `docs/spec.md` §2.8, §2.12, §3, §7, §8 M4 exit criteria **and** the overview (M4-R9, R18, R19, R20, R22; Shared contracts → UI; Privacy; Testing strategy → E2E). **Design:** `design/lines.html` ("Guides from the photo": badge "On device", Edge outline + Detail, Face construction + `.ai-box`, Body pose), `design/errors.html` (E3 "No face detected", E6 "Model download failed"), `design/mobile-flow.html` (Face construction in the phone Lines card), `design/mockup.css` (`.ai-box`, `.badge--success`).

## Global Constraints

As in the overview. E2E ports 64xx. Every E2E installs the strict network guard. Fixture photos: `src/features/images/__fixtures__/portrait.jpg` and `figure.jpg` (owner Q12), documented in that folder's `README.md`.

## Review Focus

1. **The download box never fetches before the click** (M4-R19), including after "Apply lines to all" and after a reload. E2E G-D5 counts requests.
2. **Exit criterion 1 really runs offline:** the reload in G-X1 must be served by the service worker (assert `response.fromServiceWorker()` for the app page) with `context.setOffline(true)` in force.
3. **Exit criterion 2 sees every request:** worker requests are visible on the engine under test, or the test says it can't see them and skips that engine (overview "Privacy").
4. **Live regions:** one polite region per panel for statuses; errors as `role="alert"`; progress as `progressbar` with value text; nothing announced twice (M3 #115 lesson).
5. **Phone:** the section is inside the always-open Lines card (D1-R1), 44 px controls, 16 px text.

### Task E3: E2E — exit criteria, desktop flows, privacy

**Branch:** `test/e2e-guides` · **PR title:** `test(e2e): guides exit criteria, offline and privacy` · **Depends on:** E2

- [ ] **Step 1: Helpers** (`e2e/support/app.ts`): `openGuides()`, `setGuide('face' | 'pose' | 'edges', on)`, `downloadModel('face' | 'pose')` (clicks, waits for the progress to finish), `setDetail(pct)`, `guideStatus(kind)`. `network-guard.ts`: `requestsSince(mark)` and a `seen(urlPart)` query; update its header comment (service workers allowed only in the offline spec; worker visibility per engine). `pdf.ts`: `guideStrokes(page)` = non-registration strokes, with their path ops.
**Browser matrix (`C1-R1`, binding).** Real face and pose detection runs on CI only in chromium (and mobile-chromium in E4): CI's Linux WebKit has no WebGL in a worker (the main-thread engine, tested in C4) and CI's Linux Firefox has no WebGL at all. A test that needs a real face or pose detection runs on chromium only and skips elsewhere with that reason; the rest runs on all three. Any console-error check allows exactly MediaPipe's `console.error` INFO line ("INFO: Created TensorFlow Lite XNNPACK delegate for CPU.") and nothing broader.

- [ ] **Step 2: Tests** (`e2e/offline.spec.ts`, `e2e/guides.spec.ts`, `e2e/privacy.spec.ts`; chromium, firefox, webkit unless stated):

Chromium (required) and firefox. On firefox (no WebGL on CI), face and pose take the `unsupported` path (G-U1), so there the test proves the offline reload, the edges in the preview and the PDF, and no request. webkit skips with the reason C1 found: Playwright's WebKit fails an offline reload through a service worker ("WebKit encountered an internal error"); the owner checks WebKit offline on the iPhone at sign-off.

Face and pose detection happen only on chromium (matrix above). On firefox/webkit, first assert the guard saw the model download; if it didn't, skip with "worker requests are invisible to Playwright on this engine" and keep chromium as the gate.
  - **G-P2 storage** (extends P2): `localStorage` envelope version 4 with `lineDefaults.edges.detailPct` and guides off; `caches.keys()` ⊆ {`artistica-ai-v1`, `artistica-shell-*`}; every cached request URL is an `AI_ASSETS` URL or a build file under `/artistica/`; no `blob:`; IndexedDB unused.

  - **G-D4 determinism:** (a) Remove all, add the same photos in the other order: identical guide strokes in the PDF, exact (C1: landmarks bit-identical run to run; face and pose part on chromium only); (b) the browser's edge worker output for a synthetic RGBA image equals the node golden from B2 (exact).

  - **G-D6 nothing found** (chromium): `flat-grey.png` with face and pose on: "No face found in this image." and "No person found…", switches still on, no guide strokes in the PDF.
  - **G-D7 download failure:** route the face model URL to abort once: the E6 alert; "Try again" succeeds; "Turn off face guides" turns the switch off.
  - **G-D8 edits** (chromium): rotate `portrait.jpg` 90° in the edit sheet: a new face detection (one), guides on the face; flip it: no new detection, guides mirrored; crop the face out: no face strokes.
  - **G-D9 timing** (chromium for face and pose; edges everywhere): 20 photos with every guide drawn; a thickness change redraws the preview within 1000 ms on CI (record; target < 200 ms); no detection request.
  - **G-D10 export gate** (chromium): while a detection runs (slowed by a route delay on the model's first download), Export is disabled with "Finding guides in your photos…"; it enables when the guides appear.
  - **G-A1 axe** on the Lines tab in every section state (box, progress, found, nothing found, failure), light and dark; **G-K1 keyboard only:** Tab to the section, Space toggles, Enter on "Download & turn on", arrow keys on Detail; **G-F1 forced colors** (chromium emulation): the badge, the box border and the progress bar remain visible.
