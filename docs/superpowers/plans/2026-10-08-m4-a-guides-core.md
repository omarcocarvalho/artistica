# M4-A: Guides Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the pure core of the guides from the photo: the settings fields for edge, face and pose guides; the types for landmarks and outlines found in a photo; the exact mapping from source pixels onto the picture frame; and the geometry of the face construction lines and the pose figure. Everything is plain TypeScript with no DOM, tested in node with example and property tests and recorded landmark fixtures.

**Architecture:** Detections are stored in **source coordinates** (normalised to the decoded, EXIF-corrected image, before crop, rotation and flips; M4-R7). Guide geometry is built in **source pixels** (square pixels, so circles are circles), then mapped onto the picture frame by one affine (`sourceToFrame`, M4-R10) and onto the page by M3's `frameToPage`. D3 assembles these into `TileLines`.

**Tech Stack:** TypeScript 6 (strict, `noUncheckedIndexedAccess`), Vitest 5 (`unit` project, node), fast-check 4. No new dependencies.

**Spec:** `docs/spec.md` §2.8, §2.7, §4 **and** `docs/superpowers/plans/2026-10-08-m4-overview.md` (M4-R7, R9, R10, R12–R14, R17; Shared contracts → `lines.ts`, `features/lines/guides/`). **Design:** `design/lines.html` (`data-line="face"` and `data-line="pose"` overlays: the visual reference for the construction and the figure).

**Prerequisite:** M3 released (`v0.3.0`). A1 merges before A2–A4, B3, D1, D2, E1.

## Review Focus

1. **M3 must not move.** Every setting with guides off gives the M3 `linesKey`, the M3 page models and the M3 PDF bytes. Pinned in A1 (`linesKey equals the M3 key when no guide is on`, against a frozen copy of the M3 function in the test).
2. **Rotation direction.** A landmark found in a bitmap rotated 90° clockwise must come back to the right source pixel; a sign error mirrors every face. Pinned in A2 (`fromRotated inverts the rotated bitmap's pixel mapping`, all four rotations, against a hand-rotated 3 × 2 grid).
3. **Head axis sign.** The construction must point "down" towards the chin even for an upside-down photo. Pinned in A3 (`a face rotated by 180° gives the same construction rotated by 180°`).
4. **Hidden landmarks.** A pose with a hidden wrist must drop the forearm and the wrist dot only. Pinned in A4.
5. **Budgets.** Pinned by properties: `facePaths(...).length ≤ MAX_CMDS_PER_FACE`, `poseFigure` likewise.

describe('guide settings', () => {
  it('sanitizes the guide fields field by field', () => {

    expect(DEFAULT_LINES.edges).toEqual({ on: false, detailPct: 50 })

  })
  it('lists guide types after the composition types', () => {
    const on = patchLines(DEFAULT_LINES, { pose: true, thirds: true, edges: { on: true } })
    expect(activeLineTypes(on)).toEqual(['thirds', 'edges', 'pose'])
  })
  it('linesKey equals the M3 key when no guide is on', () => {
    fc.assert(fc.property(anyLines, (raw) => {

      const off = patchLines(s, { edges: { on: false }, face: false, pose: false })
      expect(linesKey(off)).toBe(m3LinesKey(off)) // frozen copy of the M3 function, in the test file
    }))
  })
  it('linesKey adds e<detail>, f and p in that order', () => {

    expect(linesKey(s)).toBe('t,e37,f,p|#e0457b|0.35|90')
    expect(linesKey(patchLines(DEFAULT_LINES, { face: true }))).toBe('f|#e0457b|0.35|90')
  })
  it('linesKey ignores the detail while the edge outline is off', () => {
    expect(linesKey(patchLines(DEFAULT_LINES, { edges: { detailPct: 9 } }))).toBe('-')
  })
  it('withoutLineTypes turns guides off and keeps the detail', () => {
    const s = withoutLineTypes(patchLines(DEFAULT_LINES, { edges: { on: true, detailPct: 80 }, face: true }))
    expect(s.edges).toEqual({ on: false, detailPct: 80 })
    expect(s.face).toBe(false)
  })
  it('hasGuides is true only when a guide is on', () => {
    expect(hasGuides(DEFAULT_LINES)).toBe(false)
    expect(hasGuides(patchLines(DEFAULT_LINES, { pose: true }))).toBe(true)

### Task A2: Source mapping, crop culling and edge paths

**Branch:** `feat/lines-source-mapping` · **PR title:** `feat(lines): map source pixels onto the picture frame` · **Depends on:** A1

**Files:** create `src/features/lines/guides/map.ts`, `map.test.ts`, `edge-paths.ts`, `edge-paths.test.ts`; modify `src/features/lines/index.ts`.

- [ ] **Step 1: Worktree** `.worktrees/m4-a2`, branch as above.
- [ ] **Step 2: Failing tests** (`map.test.ts`):
  - `sourceToFrame agrees with orientMatrix for every rotation, flip and crop` — property: random `pxW, pxH` (1–6000), crop inside the image or null, rotation ∈ {0, 90, 180, 270}, flips; frame = the printed aspect × random scale. For random source px points, `applyAffine(sourceToFrame(img, frame), p)` equals `applyMatrix(orientMatrix(rotation, flipH, flipV, crop.w, crop.h, frame.w, frame.h, 0), p − crop.origin)` within 1e-9 mm. (Same tie M3 A2 made for `frameToPage`.)
  - `the crop's corners land on the frame's corners` — the crop's top-left goes to the frame corner that shows it after rotation and flips (table of 16 cases written by hand).
  - `fromRotated inverts the rotated bitmap's pixel mapping` — a 3 × 2 grid of labelled pixels rotated by hand 90°, 180°, 270°; each label's normalised centre in the rotated grid maps back to its source centre.
  - `fromCrop round trip` — property: `toCrop(fromCrop(p))` = p within 1e-12 (with a test-only inverse).
  - `meetsCrop` — a box wholly left of, touching, and inside the crop.
  - `cropKey` — `null` → `'full'`; fractional crops round to whole px (`{ x: 10.4, y: 0.6, w: 99.5, h: 50 }` → `'10,1,100,50'`).
- [ ] **Step 3: Failing tests** (`edge-paths.test.ts`): normalised polylines become `M` + `L…` in source px (× pxW, × pxH); a polyline of one point is dropped; a polyline wholly outside the crop is dropped, one crossing the crop edge is kept whole (the clip trims it, M3-R4); output order = input order.
- [ ] **Step 4: RED, implement, GREEN.** `sourceToFrame` composes: translate by −crop origin; scale by `1 / crop.w`, `1 / crop.h` (normalised); the rotation coefficients of `ROTATION_COEFFS` (import from `tile-plan.ts`; do not duplicate the table); flips; scale by the frame. `fromRotated` is the inverse of the rotation table on normalised coordinates.
- [ ] **Step 5: Pre-PR command, PR.**

**How each rule is tested:** a mutation of any rotation coefficient, of a flip, or of the crop origin fails `agrees with orientMatrix`; swapping `fromRotated`'s 90 and 270 cases fails the grid test.
