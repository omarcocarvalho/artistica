# M2-D: Studies UI, Shell Wiring & E2E Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give users the Studies controls (desktop Studies tab, phone Studies step), wire the study pipeline into the app shell (provider, defaults, layout memo, export pause), and prove M2's exit criterion end to end: a sheet with an image next to its blurred and 5-value versions exports and parses back correctly on every engine, on the phone, within the M1 memory budget.

**Architecture:** `StudiesPanel` is a self-contained block in `src/features/studies/components/` that reads and writes `useImages` (B1's `updateStudy` / `applyStudyToAll`) and draws its ramp strip with A4's `valueRamp`. The shell (`src/app/`) composes it: a `Tabs` "Settings" (Page | Studies) on desktop and a fifth phone step with a thumbnail picker. Two effects keep stores in step without cross-feature imports: `StudyDefaultsEffect` (settings ↔ images defaults) and the existing `PipelineEffect`, whose pipeline gains a structural layout memo (M2-R15). `PreviewSlot` hands the app's single `StudyTileProvider` (C2) to every `PagePreview`; `ExportSlot` pauses it while the export dialog is open (M2-R16). E2E specs extend M1's page objects and parse the exported PDF with B5's extended inspector.

**Tech Stack:** React 19, Zustand 5, react-i18next 17, Radix (via `src/shared/ui` primitives), Vitest 5 (`dom` project, happy-dom, Testing Library), Playwright 1.63 (+ `@axe-core/playwright`), node `zlib` for the PNG fixture.

**Spec:** `docs/spec.md` §2.6, §2.9, §2.12, §3, §7, §8 M2; **binding:** `docs/superpowers/plans/2026-10-07-m2-overview.md` (Rulings M2-R1…R17, Shared contracts → UI, Settings, Images store, Preview studies; Memory and Performance budgets; Testing strategy → E2E). **Design:** `design/studies.html` (Studies tab), `design/mobile-flow.html` (Studies step), `design/README.md`.

**Prerequisites:** A4 (`valueRamp`), B1 (store study actions), B2 (settings v2), B3 (groups in layout), B5 (export + `inspectPdf` extensions), C2 (`createAppStudyProvider`), C3 (`PagePreview` `studyTiles` prop, tile names, chips) are merged before the task that needs them (see Parallelization). ## Review Focus

Five things real users will hit that the contract does not spell out. Each has a pinned test.

1. **Dragging the blur slider on a phone with 20 photos.** Expected: no layout re-run (only the selected image's study tiles change), no stalls, and the defaults written to `localStorage` only once the value differs. Pinned in D2 (`pipeline.test.ts` "reuses the layout when only study parameters change"; `StudyDefaultsEffect.test.tsx` "writes defaults only when the selected image's blur or values change") and D4 (`S-P4` timing).
2. **Unticking the last version.** Expected: impossible; the chip says why, and the keyboard user hears it. Pinned in D1 (`keeps the last selected version and explains why`).
3. **Selecting a different photo while the Studies tab is open.** Expected: the panel follows the selection (tile click or list) and never edits the previous image. Pinned in D1 (`edits the image it is given, not the previously shown one`) and D3 (`S-D5`).
4. **"Apply to all" with many photos.** Expected: every photo gets the same versions and parameters, crop/copies untouched, the result is announced politely once, and the page count grows. Pinned in D1 (`announces how many images changed`) and D3 (`S-D4`).
5. **Exporting while study previews are still processing.** Expected: the preview queue pauses while the export dialog is open, so the phone never runs two pixel workers at once; it resumes afterwards. Pinned in D2 (`ExportSlot.test.tsx` "pauses the study provider while the dialog is open") and D4 (`M3` memory).

- [ ] **Step 2: The `value-ramp.png` fixture**

A 900 × 600 RGB PNG written in node (no browser, so it is byte-identical on every machine and does not need macOS): the top half is a horizontal grey ramp 0 → 255; the bottom half the same ramp tinted towards ochre (`r = v, g = round(v · 0.85), b = round(v · 0.55)`). Every OKLab lightness band is populated, so N-value posterisation produces exactly N tones and the percentile clip (overview Q11 default) never empties a band. Add to `generate.mjs` a pure-node section that runs with `node generate.mjs --only=value-ramp` (the existing chromium/sips sections are skipped behind that flag, so the HEIC files are not regenerated):

```js
import { crc32, deflateSync } from 'node:zlib'

function pngRgb(w, h, pixel) {
  const chunk = (type, data) => {
    const body = Buffer.concat([Buffer.from(type, 'ascii'), data])
    const out = Buffer.alloc(12 + data.length)
    out.writeUInt32BE(data.length, 0)
    body.copy(out, 4)
    out.writeUInt32BE(crc32(body), 8 + data.length)
    return out
  }
  const ihdr = Buffer.alloc(13)
  ihdr.writeUInt32BE(w, 0)
  ihdr.writeUInt32BE(h, 4)
  ihdr[8] = 8 // bit depth
  ihdr[9] = 2 // colour type: RGB
  const raw = Buffer.alloc((w * 3 + 1) * h)
  for (let y = 0; y < h; y++) {
    raw[y * (w * 3 + 1)] = 0 // filter: none
    for (let x = 0; x < w; x++) {
      const [r, g, b] = pixel(x, y)
      raw.set([r, g, b], y * (w * 3 + 1) + 1 + x * 3)
    }
  }
  return Buffer.concat([
    Buffer.from([0x89, 0x50, 0x4e, 0x47, 0x0d, 0x0a, 0x1a, 0x0a]),
    chunk('IHDR', ihdr),
    chunk('IDAT', deflateSync(raw, { level: 9 })),
    chunk('IEND', Buffer.alloc(0)),
  ])
}

export function valueRampPng() {
  const W = 900
  const H = 600
  return pngRgb(W, H, (x, y) => {
    const v = Math.round((x / (W - 1)) * 255)
    return y < H / 2 ? [v, v, v] : [v, Math.round(v * 0.85), Math.round(v * 0.55)]
  })
}
```
