# M4-C: AI Runtime, Assets and Offline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run MediaPipe Face Landmarker and Pose Landmarker in the browser from files on our own site, downloaded once with progress into Cache Storage, unable to reach any other site, in a worker that is released when idle; and keep the whole app available offline with a service worker.

**Architecture:** A time-boxed spike (C1) verifies the runtime facts the plan could not verify from documents. C2 adds the pinned package, commits the models and generates a manifest (`virtual:ai-assets`) with sizes and SHA-256, plus a build audit that no shipped file names another host. C3's loader is the only code that fetches AI bytes (Cache Storage first, verified). C4's landmark engine receives the bytes, installs a fetch guard, and creates the landmarkers from `blob:` URLs and buffers. C5's service worker caches the app shell only.

**Tech Stack:** `@mediapipe/tasks-vision@0.10.35` (new, M4-R1), Comlink, Vite 8 (rolldown) plugin API, Cache Storage, `crypto.subtle.digest('SHA-256')`, Service Worker API. Vitest (node and happy-dom), Playwright.

**Spec:** `docs/spec.md` §2.8 (models served from our own site, downloaded only when first needed, cached), §3 (privacy, bundle), §5, §9 **and** the overview ("Verified facts", M4-R1–R6, R19–R21; Shared contracts → AI runtime; Privacy). **Design:** `design/lines.html` (download box and progress), `design/errors.html` (E6 download failure).

**Prerequisite:** owner answer to **Q1** before C2 merges (C1 can run before it). If the owner picks the latest version with a blocked metrics call (Q1 b), C2 pins that version instead, C4's fetch guard becomes load-bearing (its test must show the metrics POST is refused), and the host audit's allow-list gains exactly `odml.pa.googleapis.com` with a comment; nothing else in this plan changes.

## Global Constraints

As in the overview. Additionally: **no code path fetches an AI asset except `loadAiAsset`** (reviewers grep for `fetch(` and `modelAssetPath`); the worker never receives a URL that isn't `blob:`. E2E ports 62xx.

## Review Focus

1. **No request leaves our origin** (M4-R1, R3, R4): the host audit, the guard, and the loader's URL source. A guard that can be bypassed by `importScripts` or `new Worker` is a blocker.
2. **Integrity:** a corrupt or truncated download never enters the cache and never reaches MediaPipe (C3).
3. **Memory release:** the worker really terminates after 30 s idle, and a detection after that works without network (C4, fake timers + E3).
4. **Service worker scope:** it never caches a link import, a `blob:`, a POST, or the AI assets, and never calls `skipWaiting` (C5).
