# M4-B: Edge Outline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Our own edge outline (spec §2.8: "a classic edge-detection algorithm (Sobel/Canny, written by us and run in a worker; no AI model needed). Adjustable detail level."). From an RGBA image of the cropped picture (≤ 1024 px), produce a budgeted set of simplified polylines, deterministically, in a worker with a main-thread fallback.

**Architecture:** A pure pipeline over typed arrays: grey → binomial blur → integer Sobel → non-maximum suppression → percentile thresholds → hysteresis → 8-connected chain tracing → Ramer–Douglas–Peucker → longest-first budget (M4-R15, M4-R16). The worker wraps it with Comlink exactly like the studies worker (`src/features/studies/preview/`), taking ownership of a transferred `ImageBitmap`.

**Tech Stack:** TypeScript 6, Vitest 5 (`unit` node project; `perf` project for timing), fast-check 4, Comlink (already a dependency), `OffscreenCanvas` in the worker. No new dependencies.

**Spec:** `docs/spec.md` §2.8, §3 (heavy processing loads only when needed), §7 **and** the overview (M4-R6, R7, R15, R16; Shared contracts → Edge outline; Memory and Performance budgets). **Design:** `design/lines.html` (`data-line="edge"`: an outline drawing of the main shapes, not a texture; Detail slider 1–100%, default 50%).

## Global Constraints

As in the overview. Pure files (`detail.ts`, `canny.ts`, `trace.ts`, `simplify.ts`, `outline.ts`) have no DOM and no floating-point transcendental functions (`Math.exp`, `Math.atan2`, `Math.hypot`, `Math.sqrt` are banned in them; a lint-free grep check runs in the B1 and B2 tests: `the edge core uses no transcendental Math functions`, reading the source files). E2E ports 61xx.

## Review Focus

1. **Bit-identical across engines.** Integer arithmetic only (M4-R15). The golden snapshot (B2) runs in node; E3 compares the browser worker's output for the same RGBA input with the node result (G-D4 part b).
2. **Detail is monotonic** in edge pixels: the edge map at a higher detail contains the one at a lower detail (B1 property, every step 1 → 100; B1-R1 fixes the blur so it holds). Chain and vertex counts are not monotonic by construction (an added pixel can join two chains or split one), so B2 pins coverage, not counts.
3. **Budget order is deterministic:** longest chain first, ties by the first point's scan index. Pinned in B2.
4. **No outline from smooth shading:** a linear gradient gives no edges at any detail. Pinned in B1.
5. **Ownership:** the worker closes the bitmap on every path, success or failure (B3).

### Task B1: Integer Canny

**Branch:** `feat/lines-edge-detect` · **PR title:** `feat(lines): detect edges with an integer Canny` · **Depends on:** —

- [ ] **Step 1: Worktree** `.worktrees/m4-b1`.
- [ ] **Step 2: Failing tests** `detail.test.ts`:
  - `maps 1, 50 and 100 to the pinned parameters`: 1 → `{ blurPasses: 2, keepShare: 0.03, minChainPx: 48 }`, 50 → `{ blurPasses: 2, keepShare: 0.114, minChainPx: 27 }`, 100 → `{ 2, 0.2, 6 }`, with `t = (d − 1) / 99`, `blurPasses = EDGE_BLUR_PASSES = 2` (B1-R1), `keepShare = round3(0.03 + 0.17t)`, `minChainPx = round(48 − 42t)`;
  - `clamps and rounds outside 1–100`; `is monotonic` (property).
  `canny.test.ts`:
  - `toGrey uses (77R + 150G + 29B) >> 8 and ignores alpha`;
  - `a white square on black gives a closed 1-px ring on its border at every detail`;
  - `a linear gradient gives no edges at any detail` (property over directions);
  - `a disc gives a ring within 1 px of its radius`;
  - `edges are one pixel wide after non-maximum suppression` (no 2 × 2 block of edge pixels on the disc);
  - `higher detail never gives fewer edge pixels` (property on noise images: for every d from 1 to 99, the edge map at d + 1 contains the one at d);
  - `the same input gives the same output` and `transposing the input transposes the output` (except for the documented tie-break of equal magnitudes, which is defined so the transpose holds: compare `>` on one side and `>=` on the other, symmetric under transpose);
  - `the edge core uses no transcendental Math functions` (reads `canny.ts` and `detail.ts` source).
- [ ] **Step 3: RED, implement, GREEN.**
  - Blur: 1-4-6-4-1 in x and y, edges clamped, the exact 2D integer sum divided once (`>> 8`) per pass (B1-R4).
  - Sobel: `gx`, `gy` in `Int32Array`; magnitude² in `Float64Array` is not allowed: use `Int32Array` of `gx² + gy²` (max 2 × 1020² fits).
  - Direction sector by integer comparison (overview M4-R15); NMS against the two neighbours of the sector: ≥ the one the gradient points to, > the one behind, outside the image counts as 0 (B1-R3).
  - Thresholds: sorted magnitude² of the NMS survivors (B1-R5); `high` = the smallest of the strongest `max(1, ⌊n · keepShare⌋)`, at least `MIN_STRONG_MAG2 = 32²` (B1-R2); `low = high × 4 / 25` (i.e. 0.4² on squared values).
  - Hysteresis: explicit `Int32Array` stack; 8-connected.

### Task B2: Tracing, simplification and the budget

**Branch:** `feat/lines-edge-trace` · **PR title:** `feat(lines): trace and simplify edges into a budgeted outline` · **Depends on:** B1

- [ ] **Step 1: Failing tests** `trace.test.ts`:
  - `a ring traces to one closed chain`; `a T junction traces to chains that cover every pixel once`;
  - `chains start at the first unvisited endpoint in scan order, then at the first unvisited pixel of a loop` (fixed order);
  - `every edge pixel is in exactly one chain` (property on random edge maps).
  `simplify.test.ts`:
  - `rdp keeps the end points`, `a straight run becomes two points`, `a square ring becomes its 4 corners plus the closing point`, `every dropped point is within epsilon of the kept polyline` (property).
  `outline.test.ts`:
  - `chains shorter than minChainPx are dropped`;
  - `the outline keeps at most MAX_EDGE_VERTICES points, longest chains first, ties by first point` (noise image at detail 100);
  - `points are pixel centres normalised to the image: ((x + 0.5) / w, (y + 0.5) / h)`;
  - `the chains cover exactly the edge pixels at every detail` (property; with B1's property, coverage grows with detail) and `on the still life, more detail gives more kept vertices` (detail 25 < 50 < 75, a fixture check, not a property: chain and vertex counts can drop when an added pixel joins two chains or splits one at a junction, B1-R1);
  - **golden:** `edgeOutline of the synthetic still life at detail 50` → snapshot of the polylines (rounded to 1e-6), plus vertex count;
  - `EDGE_ANALYSIS_LONG_SIDE is 1024 and MAX_EDGE_VERTICES is 4000` (constants pinned).
  `perf.test.ts` (perf project): `a 1024 × 768 noise image at detail 100 in under 300 ms` (CI bound 2000 ms; record the time).
- [ ] **Step 2: RED, implement, GREEN.** Coordinates stay integers until the final normalisation. RDP compares squared distances to the segment AB without a square root, scaled by |AB|²: `cross²` when the point projects inside AB, `|AP|² · |AB|²` before A, `|BP|² · |AB|²` past B; the point is within ε when that is `≤ ε² · |AB|²` (all integers; ε = 1; B2-R1). The budget visits chains longest first (pixel count before simplification, ties by the first point's scan index) and skips a chain that does not fit, still trying shorter ones (B2-R2).
- [ ] **Step 3: Pre-PR command, PR** (attach the golden image with its outline drawn, from a throwaway script).
