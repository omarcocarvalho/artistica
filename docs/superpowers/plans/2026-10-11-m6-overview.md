**Goal:** Ship `v1.0.0`:

- **The app in seven languages:** English, Portuguese (Brazil), Japanese, Korean, Italian, Spanish (neutral) and Chinese (Simplified), chosen by the saved choice, else the browser language, else English (spec §2.10). Numbers, units and plurals follow each language. Every language except English loads only when it is needed, so the initial app JS stays under 250 KB gzip.
- **Every deferred i18n bug fixed:** no message built by concatenation, no raw ids or unit codes on screen, no number formatted by hand.
- **Translated landing pages** (`/pt-BR/`, `/ja/`, …), pre-rendered static HTML with `hreflang`, canonical URLs, a sitemap, Open Graph tags and translated FAQ structured data (spec §2.11, Q36). The privacy text stays accurate in every language.
- **CJK text that fits and renders correctly** (spec §8 M6): font stacks per language, line breaking per language, and a long-text check that catches overflow.
- **Every screen reviewed in all 7 languages** (the spec's exit criterion), defined concretely in M6-R26: automated screenshot sets and axe scans per language, plus a recorded controller pass, so the owner's review at 1.0 is quick.
- **1.0 readiness:** each item M5 deferred to M6 fixed or dropped, the `Release-As: 1.0.0` mechanics, and final docs (README, HANDOVER, landing copy).

**Spec:** `docs/spec.md` §2.10 (languages; R9: translations by Claude, native review welcome later; R10: pt-BR, zh-CN Simplified, neutral Spanish), §2.11 (SEO; localized landing in M6, Q36), §2.12 (look and feel, WCAG 2.2 AA), §3 (bundle < 250 KB gzip; privacy; reliability), §7, §8 "M6 — Translations & 1.0" (exit: every screen reviewed in all 7 languages; 1.0 released), review round 1 D4 (language picker hidden until M6) and D5 (self-hosted Latin fonts; "CJK uses system fonts", `design/README.md` open question 5). **Design:** `design/workspace.html:25-26` and the other desktop mockups put a language `<select>` in the app top bar; `design/landing.html:96` puts one in the landing footer; no mockup shows the phone placement or CJK text (D1 adds them). **Conventions:** `CLAUDE.md`. **Constraints carried over:** the M1–M5 overviews' contracts and rulings, the ledgers (`docs/superpowers/ledgers/*.md`) and `HANDOVER.md`.

**M6 exit criteria (spec §8, plus the delegation):**

- All six translations ship for the app UI and the landing page; the locale check (A4) passes in CI: every key in every locale, the same interpolation variables and `<n>` tags, the plural categories each language needs (CLDR), and no stale translation.

- Initial app JS < 250 KB gzip with every language present (the required `build` check), and no non-English string in the initial chunks (A1 marker check).
- The UI language never changes the output: the same photos and settings give a byte-identical PDF in every language (L10N-D1, M6-R24).
- All tests green on all required checks; unit coverage ≥ 80% on the M5 list plus `src/shared/i18n/**` (A1 adds it to the coverage `include`).
- The final review F (three parts) is clean, master CI is green, the M6 ledger holds the evidence, the `Release-As: 1.0.0` commit is on master and the release PR reads `chore(master): release 1.0.0`. **Then M6 is ready for the owner's v1.0.0 sign-off** ("Owner's v1.0.0 sign-off checklist" below). ## Rulings made in this plan (technical, not product)

Each ruling is binding for the sub-plans. Rulings marked "(owner Qn, default)" implement a recommended default and change only if the owner answers otherwise at the v1.0.0 sign-off.

**General**

- **M6-R1 No new dependencies.** i18next 26 already formats through `Intl`; `Intl.NumberFormat`, `PluralRules`, `ListFormat` and `DateTimeFormat` cover numbers, units, plurals, lists and dates; CJK uses system fonts (M6-R17); the landing pages are rendered by our own Vite plugin. `package.json` and the lockfile do not change in M6, except the `scripts` entries named in this plan. A task that finds it needs a package stops and asks the controller, who brings it to the owner.
- **M6-R2 Language codes.** The seven codes of `LANGUAGES` are used unchanged everywhere: `<html lang>`, `hreflang`, URL path segments (`/artistica/pt-BR/`, case as written; GitHub Pages is case-sensitive), locale folder names and settings. English has no path segment (M6-R20). `og:locale` maps them to `en_US`, `pt_BR`, `ja_JP`, `ko_KR`, `it_IT`, `es_LA`, `zh_CN`.

**Runtime (A)**

- **M6-R3 Which language is shown.** In order: (1) the saved choice (`settings.language`); (2) the one-time `?lang=<code>` hint a translated landing page puts on its app link (owner Q7, default); (3) the browser's `navigator.languages`, walked in order through M6-R4; (4) English. The hint is never saved; the app removes it from the address bar with `history.replaceState` after reading it. Only a choice in the app's switcher is saved (M6-R15).
- **M6-R4 Matching a browser language.** `matchLanguage(tags: readonly string[]): LanguageCode | null`, a pure function, case-insensitive, `_` read as `-`: an exact code wins; then `pt-*` → `pt-BR`, `es-*` → `es`, `it-*` → `it`, `ja-*` → `ja`, `ko-*` → `ko`, `en-*` → `en`, and `zh`, `zh-CN`, `zh-SG`, `zh-Hans*` → `zh-CN`; `zh-TW`, `zh-HK`, `zh-MO` and `zh-Hant*` match nothing, so the walk goes on to the next browser language (owner Q8, default). Anything else matches nothing. The i18next `LanguageDetector` is no longer used by the init (`i18next-browser-languagedetector` stays in `package.json` until a later cleanup, so the lockfile doesn't change, M6-R1).
- **M6-R5 Lazy locale bundles.** English stays in the main chunk (it is the fallback and must be synchronous). Every other language loads on demand as **one chunk per language** (`locale-<code>-[hash].js`, rolldown chunk groups in `vite.config.ts`), through a non-eager glob that excludes `en`. `loadLanguage(code)` resolves once all its namespaces are added with `addResourceBundle`; `setAppLanguage(code)` awaits it and only then calls `changeLanguage`, so the UI never shows a half-translated screen. At boot, `main.tsx` resolves the language (M6-R3), loads it, then renders: a non-English first paint waits for one same-origin chunk (precached by the service worker after the first visit). A failed load keeps the current language (English at boot) and shows the error toast "Couldn't load that language. Check your connection and try again." in the language showing. The build fails if an initial chunk contains a marker string from a non-English locale (`LOCALE_MARKERS`, next to `LAZY_ONLY_MARKERS`).
- **M6-R6 Page language attributes.** On every `languageChanged`: `document.documentElement.lang = code`, `dir = i18n.dir(code)` (`ltr` for all seven; the code path stays so a right-to-left language later needs no new mechanism), and `document.title = t('app:documentTitle')` (en "Artistica app"). The static `app/index.html` keeps `lang="en"` until the script runs.
- **M6-R7 Numbers.** Every number shown to a person goes through `src/shared/i18n/format.ts`, which builds `Intl.NumberFormat` objects once per (language, options) and caches them. Display rounding is unchanged (`roundForUnit`: 1 decimal for mm, 2 for inches; percent and degrees as integers; megabytes 1 decimal). **Editable fields** show the language's decimal separator with **no grouping** (`useGrouping: false`), so `1200` mm stays `1200` and `12,5` round-trips through `parseDecimal`; `aria-valuenow` stays a plain number. No `String(n)`, `toFixed` or template literal turns a number into UI text outside `format.ts`: a unit test scans `src/**/*.{ts,tsx}` (tests excluded) for `toFixed(` and `String(roundForUnit` and fails on a hit outside `format.ts`.
- **M6-R8 Units (owner Q6, default).** Lengths are formatted by `Intl.NumberFormat(code, { style: 'unit', unit: 'millimeter' | 'inch', unitDisplay: 'short' })`, so each language gets its CLDR symbol and spacing (`12,5 mm`, `1,5 pol.`, `12.5毫米`, `12.5mm`). A field's separate unit suffix comes from the same formatter's `unit` part (`unitLabel(unit, code)`). Megabytes use `unit: 'megabyte'`, percentages `style: 'percent'` on `value / 100`, degrees `unit: 'degree'`. The `common:units.*` and `pageSetup:units.*` keys and the raw `{{unit}}` interpolations go; the long unit names of the units control (`pageSetup:paper.unitMm`, `unitIn`) stay translatable text.
- **M6-R9 Plurals.** A plural key has exactly the suffixes `Intl.PluralRules(code).resolvedOptions().pluralCategories` lists: `_one`, `_other` (en); `_one`, `_many`, `_other` (pt-BR, it, es); `_other` only (ja, ko, zh-CN). A `_zero` form is optional in any language; i18next uses it for a count of 0 (useful in pt-BR, where CLDR puts 0 in `one`, wherever "0 imagem" reads wrong). `count` is always passed as a number and shown through i18next's built-in `{{count, number}}` format, so it gets the language's separators.
- **M6-R10 One key per message.** A user-visible message is one key with interpolation, never two keys joined in code. Two sentences that must stay separate keys are joined only by `joinSentences(t, a, b)` (key `common:joinSentences`: `"{{a}} {{b}}"` in en, `"{{a}}{{b}}"` in ja and zh-CN); a list of names uses `Intl.ListFormat`; a label with a value uses one key such as `app:theme.changeLabel` `"Change theme: {{current}}"`, whose visible part stays inside the accessible name (WCAG 2.5.3). A paper is shown through `paperName(id, t)` (M6-R25).
- **M6-R11 The locale check.** `scripts/check-locales.ts` (`pnpm i18n:check`, also run by a unit test so the required `unit` job runs it) fails when, for any non-English locale: a namespace file is missing or extra; a key is missing or extra (plural keys compared by base key); a value is empty or not a string; the set of `{{variables}}` (with any format suffix, e.g. `{{count, number}}`) differs from English; the `<0>…</0>` tags of a `<Trans>` string differ; a plural key lacks a category M6-R9 requires or has one the language doesn't use (`_zero` allowed); a translation is stale (M6-R12). It checks the landing locales (`landing/locales/*.json`, C1) the same way. It prints a warning, not a failure, when a non-English value equals the English one and the key is not on the reviewed `SAME_AS_ENGLISH` list (e.g. `PDF`, `DPI`, `A4`).
- **M6-R12 Stale translations.** `src/locales/translated-from.json` records, per language and key, a short hash of the English text it was translated from; `pnpm i18n:stamp <code> [keys…]` writes them. A change to an English value without a re-stamp in every language fails the check, naming the keys to re-translate. The file is not shipped.
- **M6-R13 String freeze.** English strings freeze when D3 merges (wave 3); the translation tasks start from that master. After the freeze, a PR that adds or changes an English string changes it in all seven locales in the same PR and re-stamps them (the check enforces it). The controller allows a freeze break only for a fix a review asks for.
- **M6-R14 Pseudo-locale.** `pseudoLocalize(text)` (pure) wraps a string in `⟦…⟧`, swaps Latin letters for accented look-alikes and pads it: ×2 up to 10 characters, ×1.8 up to 20, ×1.4 above (longer than any expected Romance expansion), leaving `{{variables}}`, `<n>` tags and `$t()` nesting untouched. The app builds the pseudo resources from English at runtime only when the app URL has `?pseudo=1`; it is a lazy chunk, never in `LANGUAGES`, never in the switcher and never saved. E2E uses it to find hard-coded text (anything visible without `⟦`) and overflow (D3).
- **M6-R15 The language switcher (owner Q1, default).** A native `<select>` with a globe icon and the visually hidden label "Language", in the app top bar at every width (the endonym shows from `sm` up; at phone width only the globe shows, and the select still opens the native picker). Options are endonyms (`English`, `Português (Brasil)`, `日本語`, `한국어`, `Italiano`, `Español`, `简体中文`; owner Q17, default), each with its own `lang` attribute; no "Automatic" entry. Choosing one saves it (`setLanguage`) and switches through `setAppLanguage`, with focus kept on the select. The language stays per tab like the theme (M5 Q22).
- **M6-R16 Messages already on screen keep their language.** Notices, toasts and live announcements are text when posted (`useNotices.notify(kind, message)`), so after a switch they keep the old language until they go. Everything rendered from keys switches at once.

**Typography and fit (D)**

- **M6-R17 Fonts (owner Q4 and Q11, defaults).** System fonts for CJK, no font download. A `:lang()` block per CJK language puts that language's own fonts first after the Latin family, so Han characters get the right regional glyphs (a Chinese page must not take its Han glyphs from a Japanese font, which today's single stack does on macOS):
  - `ja`: `"Hiragino Sans", "Hiragino Kaku Gothic ProN", "Yu Gothic UI", "Yu Gothic", Meiryo, "Noto Sans JP", "Noto Sans CJK JP"`;
  - `ko`: `"Apple SD Gothic Neo", "Malgun Gothic", "Noto Sans KR", "Noto Sans CJK KR"`;
  - `zh-CN`: `"PingFang SC", "Hiragino Sans GB", "Microsoft YaHei UI", "Microsoft YaHei", "Noto Sans SC", "Noto Sans CJK SC"`.

  In a CJK language `--font-display` and `--font-hand` use the same CJK sans after their Latin family (headings at the display weight; no serif or handwriting CJK font). The shared default stack drops its CJK names (the `:lang()` blocks own them). The three Latin fonts are unchanged: their Latin and Latin-ext subsets cover Portuguese, Spanish and Italian. A self-hosted CJK subset was rejected: 300–500 KB of WOFF2 per language and weight, glyphs still missing for whatever a person types (preset and file names), and no gain over the fonts every supported OS ships. Privacy is the same either way (self-hosted, never a CDN).
- **M6-R18 Line breaking.** `:lang(ja)`, `:lang(zh-CN)`: `line-break: strict; word-break: normal; overflow-wrap: anywhere`; Japanese headings and buttons also get `word-break: auto-phrase` (Chromium; ignored elsewhere). `:lang(ko)`: `word-break: keep-all; overflow-wrap: anywhere` (Korean breaks at spaces). Every language: `overflow-wrap: anywhere` on text inside fixed-width controls (chips, tabs, segmented options, buttons). `font-synthesis: none` in the CJK blocks (no fake bold or italic on CJK glyphs). No `hyphens: auto` (dictionaries differ between engines).

**Landing pages (C)**

- **M6-R19 How the landing pages are built.** One template, `landing/page.html` (today's `index.html` with each translatable text, attribute and JSON-LD value replaced by `{{t:key}}`), and one JSON file per language, `landing/locales/<code>.json`. A Vite plugin, `scripts/vite-landing.ts`, renders the template for every language at build into `.landing/<code>/index.html` (gitignored), adds each as a build input, and renames the emitted HTML to `index.html` (English) and `<code>/index.html` in `generateBundle`; the dev server renders the same pages on request through `transformIndexHtml`. The root `index.html` goes (the plugin owns `/`). Every page goes through the same Vite pipeline: Tailwind, hashed assets, `/landing/main.ts`. Rendering escapes every value for its context (text, attribute, JSON string); only `<strong>`, `<em>` and `<abbr>` pass through, and only in keys ending `Html`. If C1's first step finds a Vite 8 behaviour that blocks the rename (recorded in the ledger), the fallback is committed generated pages with a drift test that renders the template and compares; `dist` is the same either way.
- **M6-R20 URLs and canonical (owner Q3, default).** English stays at `/artistica/` (no `/en/`); the others are `/artistica/<code>/`. ## Determinism

- **Layout and PDF** don't read the UI language: L10N-D1 (E1) exports the same photos and settings in `en` and `ja` and compares the PDF bytes; the golden snapshot is unchanged.

- **Landing pages** are a pure function of the template and the locale files: the build renders byte-identical HTML twice (C1).
- **File names** are ASCII ids and ISO dates in every language (M6-R25).

## Accessibility

- `<html lang>` and `dir` follow the language (M6-R6); every switcher option and landing language link carries its own `lang` (WCAG 3.1.1, 3.1.2); screen readers then use the right voice (the owner's VoiceOver pass at 1.0 checks one CJK language).
- axe in every language on every screen of the set (violations and reviewed `incomplete`; `html-has-lang`, `html-lang-valid`, `valid-lang` included), light and dark on desktop.
- The switcher is a native `<select>` with a visible-or-hidden label "Language", 44 px on touch screens; changing it keeps focus.
- Longer translations don't break the 44 px targets, the 16 px phone inputs, focus outlines or reflow at 320 px (D3 overflow probe at phone width, WCAG 1.4.10).
- Label in name (2.5.3) holds in every language: the check in D3 compares each control's visible text with its accessible name.

- **Runtime (A):** `matchLanguage` and `resolveLanguage` table tests (every row of M6-R4, including `zh-TW` skipping to the next tag) and a fast-check property (the result is always one of the seven; the saved choice always wins); `loadLanguage` with fake loaders (idempotent, failure keeps the language); the document attributes; `format.ts` table tests against Node's `Intl` for all seven languages, a round-trip property (`parseDecimal(formatLengthValue(x))` equals the rounded `x` in every language), and the no-hand-formatting scan; the locale check's own fixtures (one per problem kind); behaviour tests for each fixed message.
- **Translations (B):** the locale check and stamps; per-language unit tests that render a sample of components in that language (no English text, plurals at 0, 1, 2, 5 and 1,000,000); each task's screenshots reviewed in its PR.
- **Landing (C):** render tests (escaping per context, every key present, `hreflang` set, canonical, JSON-LD parses and matches the visible FAQ), sitemap tests, build tests on `dist` (seven pages, each `lang` right), E2E per language (SEO metadata, axe, no horizontal scroll at phone width, links to the app with `?lang`, theme toggle labels).
- **Design and fit (D):** CSS tests (`:lang()` stacks contain the language's fonts first; the shared stack has no CJK names), computed-style E2E per CJK language, and the pseudo-locale probes over every screen in required CI.
- **Screens and 1.0 (E):** `l10n.spec.ts` in required CI (chromium and mobile-chromium run all seven languages; firefox, webkit and mobile-webkit run `ja` and `pt-BR`), `screens.spec.ts` on demand, L10N-D1, and unit and E2E tests for E3–E5.
- **Mutation-checked reviews** as in M1–M5: each reviewer breaks each pinned invariant once and confirms a test fails, with a mutation table in the review comment.

## Questions for the owner

> **How to answer:** each question has a recommended default, and the plans build it, marked "(owner Qn, default)" in the rulings and sub-plans. Under the owner's delegation of 2026-10-10 the controller accepted every default, so M6 needs no answer to proceed. Answer "ok" at the v1.0.0 sign-off to keep a default, or write your own answer after **A:** to change it.

Q1. **Where you choose the language.**
   _Recommendation:_ a language menu with a globe icon in the app's top bar, on desktop and phone (on the phone only the globe shows; it opens the phone's own picker). It lists each language in its own name. Choosing one switches at once and is remembered on this device. No "Automatic" entry: until you choose, the app follows your browser. On the landing page, the seven languages are links in the footer.
   **A:** accepted (recommended default), controller under the owner's delegation, 2026-10-11.

Q2. **How formal each translation is.**
   _Recommendation:_ friendly and direct everywhere, like the English: Portuguese **você** (Brazilian standard); Spanish **tú**, neutral Latin American vocabulary without regional slang or *vos*; Italian **tu**; Japanese polite **です・ます** for sentences and short noun or verb forms for buttons ("写真を追加"); Korean polite **해요체** for messages and short noun forms for buttons ("사진 추가"); Chinese **你**, plain and neutral. The full rules are in `docs/i18n/style-guide.md` (B1).
   **A:** accepted (recommended default), controller under the owner's delegation, 2026-10-11.

Q3. **The English landing page's address.**
   _Recommendation:_ English stays at `https://omarcocarvalho.github.io/artistica/` (no `/en/`), which is also the default page for search engines (x-default); the others are `/artistica/pt-BR/`, `/ja/`, `/ko/`, `/it/`, `/es/`, `/zh-CN/`. The root page doesn't redirect by browser language (it would hide the English page from search engines and needs a server); visitors use the footer links.
   **A:** accepted (recommended default), controller under the owner's delegation, 2026-10-11.
