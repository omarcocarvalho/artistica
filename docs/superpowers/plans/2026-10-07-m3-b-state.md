# M3-B: Line State Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keep line settings per image in the images store, with "Apply lines to all" and a default for new photos (B1); persist the line defaults in the settings, schema v3 (B2); and rank identical photos by their lines as well as their studies, so layouts stay independent of input order (B3).

**Architecture:** Mirrors M2's study state exactly. The images store owns `lines` per image, `updateLines`, `applyLinesToAll` (recording `appliedLines`) and a module-level default read at the end of each decode. The settings store owns the persisted `lineDefaults`; the Zod schema checks types only and `normalizeLineDefaults` (built on `sanitizeLines`) owns every range. The two stores never import each other; D2's `LineDefaultsEffect` connects them.

**Tech Stack:** TypeScript 6, Zustand (+ `persist`), Zod, Vitest 5 + fast-check. No new dependencies.

**Spec:** `docs/spec.md` §2.7 (per image, "apply to all"), §2.9 (default line settings remembered) **and** `docs/superpowers/plans/2026-10-07-m3-overview.md` (M3-R1, R16, R17; Shared contracts → Images store, Settings, Layout; owner Q7, Q8 defaults). M2 references: `src/features/images/store.ts` (`updateStudy`, `applyStudyToAll`, `setDefaultStudy`), `src/features/settings/{schema,store}.ts` (study defaults, v1 → v2), `src/features/layout/build-items.ts` (`printedStudies`).

**Prerequisite:** A1 merged (`LineSettings`, `DEFAULT_LINES`, `ImageDescriptor.lines`). B1, B2 and B3 run in parallel (wave 2) with A2 and A3.

## Review Focus

1. **Studies and Lines stay independent (D7).** `applyLinesToAll` never touches `study` or `edits`; `applyStudyToAll` never touches `lines`. Pinned in B1, both directions.
2. **An import that finishes after the default changed** takes the new default (read at the end of decode, as M2 B-CR3). Pinned in B1.
3. **Old saved settings.** A v2 envelope (M2) and a v1 envelope (M1) load with every field kept and `lineDefaults` = defaults. One corrupt `lineDefaults` field keeps the others. Pinned in B2.
4. **Line types are not remembered** (owner Q7, default): a stored `lineDefaults` with `thirds: true` loads with `thirds: false`; style, grid size and corner survive. Pinned in B2, at one switch point (`normalizeLineDefaults`).
5. **Twins with different lines.** Two copies of one file, one with thirds and one without, must give the same layout whichever is added first. Pinned in B3; with no lines anywhere the golden snapshot is unchanged.

- [ ] **Step 3: Implement** next to the study actions:

```ts
let defaultLines: LineSettings = DEFAULT_LINES
// in loadOne, where `study: defaultStudy` is set:
//   lines: defaultLines,

appliedLines: null,

updateLines: (id, patch) => {
  set((s) => {
    let changed = false as boolean
    const images = s.images.map((img) => {
      if (img.id !== id) return img
      const lines = patchLines(img.lines, patch)
      if (linesEqual(lines, img.lines)) return img
      changed = true
      return { ...img, lines }
    })
    return changed ? { images } : s
  })
},

applyLinesToAll: (fromId) => {
  const { images } = get()
  const lines = images.find((i) => i.id === fromId)?.lines
  if (lines === undefined) return 0
  let count = 0
  const next = images.map((img) => {
    if (linesEqual(img.lines, lines)) return img
    count += 1
    return { ...img, lines }
  })
  set(count > 0 ? { images: next, appliedLines: { lines } } : { appliedLines: { lines } })
  return count
},

setDefaultLines: (lines) => {
  defaultLines = sanitizeLines(lines)
},
```

Add the three actions and `appliedLines` to `ImagesState` with the overview's doc comments; `clear()` resets `appliedLines` like `appliedStudy`. Tests → PASS.

- [ ] **Step 3: Implement.**

```ts
// schema.ts
import { DEFAULT_LINES, sanitizeLines, withoutLineTypes, type LineSettings } from '../../shared/model/lines'

const L = DEFAULT_LINES
/** Total and types-only (M3-R16, M2 ruling B2): ranges belong to sanitizeLines. Unknown keys are stripped. */
const lineDefaultsSchema = z.object({
  grid: z.object({
    on: z.boolean().catch(L.grid.on),
    cols: z.number().catch(L.grid.cols),
    rows: z.number().catch(L.grid.rows),
  }).catch(L.grid),
  thirds: z.boolean().catch(L.thirds),
  armature: z.boolean().catch(L.armature),
  golden: z.boolean().catch(L.golden),
  spiral: z.object({
    on: z.boolean().catch(L.spiral.on),
    corner: z.string().catch(L.spiral.corner), // validity is sanitizeLines' job
  }).catch(L.spiral),
  centre: z.boolean().catch(L.centre),
  style: z.object({
    colour: z.string().catch(L.style.colour),
    widthMm: z.number().catch(L.style.widthMm),
    opacityPct: z.number().catch(L.style.opacityPct),
  }).catch(L.style),
})

/** The one normalisation, on load and in setLineDefaults (owner Q7 default: types are not remembered). */
export function normalizeLineDefaults(lines: LineSettings): LineSettings {
  return withoutLineTypes(sanitizeLines(lines))
}
// settingsSchema gains: lineDefaults: lineDefaultsSchema.catch(L)
// DEFAULT_SETTINGS gains: lineDefaults: DEFAULT_LINES
// parseSettings returns: { ...parsed, pageSetup, studyDefaults: …, lineDefaults: normalizeLineDefaults(parsed.lineDefaults as LineSettings) }
```

The `corner` string passes the schema as a plain string and is narrowed by `sanitizeLines` (the cast is documented in a comment). In `store.ts`: `SETTINGS_VERSION = 3`; `setLineDefaults: (lines) => set({ lineDefaults: normalizeLineDefaults(lines) })`; `partialize` adds `lineDefaults`; `migrate` stays `parseSettings` (its comment: "Runs for v1, v2 and any other version…"). Export `normalizeLineDefaults` and the type from `index.ts`. Tests → PASS.
