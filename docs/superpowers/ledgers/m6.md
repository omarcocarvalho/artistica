## E4

PR #191 (`fix/arrange-ghost-clip`), squash-merged; merge commit: see git log. Independent review, no fix round needed.

- **Contract:** the drag ghost is portalled to `document.body`, `position: fixed` in viewport pixels (from the hit sheet's client rect, recomputed on every move and scroll), `z-index: var(--z-popover)` (above panels and the top bar, below toasts and dialogs), `aria-hidden`, `pointer-events: none`; it goes on pointer up, Escape, `pointercancel` and unmount mid-drag. The swap target stays on the sheet in sheet pixels. The drag path is otherwise unchanged (no layout call or redraw during a drag, M5-R19 test green); no renderer, string, dependency, storage or network change. `base.css`'s `body > *` (`position: relative; z-index: 1`) is in the base layer, so the components-layer rule wins (E2E reads the computed values).
- **Accessibility:** the ghost was and stays decorative (`aria-hidden`); the refusal is still announced once on release (B-D10 asserts the live region). Forced-colours rules still match the ghost outside the layer. On the phone the preview is not inside a dialog, so no modal layer sits above `--z-popover` during a drag.
- **Checks (reviewer, own worktree):** lint, format:check, typecheck, test:coverage (3499 passed, 98.63 % statements), test:perf (16), build: green. E2E port 5208, `arrange.spec.ts` + `arrange-phone.spec.ts` on chromium, firefox, webkit, mobile-chromium, mobile-webkit: 49 passed, 46 skipped by project.
- **Reviewer mutations:** unit — portal into `body.firstElementChild` (R1), swap target in viewport pixels (R2), move ghost in sheet pixels (R3), resize ghost in sheet pixels (R4), `z-index: var(--z-panel)` (R5), `--on-paper-*` only on the layer (R6), no `aria-hidden` (R7), viewport origin off by 1 px (R8): all killed. E2E (B-D10, chromium + webkit) — ghost rendered inline in the layer, with fixed positioning and viewport pixels kept: killed, but only by the "not inside `main#main`" count; `position: absolute; z-index: 5` with the portal kept: survives the E2E, killed by `arrange-css.test.ts`.
- Ruling: the mutation results show that in today's DOM `position: fixed` alone already escapes the scroller's overflow clip (no transformed or `contain` ancestor), so the portal is defence against a future transform, containment or stacking context on the preview path. It is pinned by the unit tests (parent is `body`) and by B-D10's containment count; `fixed` over `absolute` is pinned only by the CSS test, since the window does not scroll. Accepted as sufficient.
- Ruling (deviation 1): portal target `document.body`, accepted. No preview overlay root exists; `body` is where the Radix overlays already portal.
- Ruling (deviation 2): the E2E drags past the left edge, not the bottom, accepted. Verified: the desktop shell is `h-dvh` (`src/app/App.tsx:28`) with `main#main` reaching the viewport's bottom, so a ghost past the bottom edge can never be fully in the viewport; the left corners checked by `elementFromPoint` are the ones outside the scroller.
- Ruling (deviation 3): hit-testing switched on for the single `elementFromPoint` call, with computed `pointer-events: none` asserted separately, accepted; it is the only way to satisfy both plan assertions.
- Ruling (deviations 4, 5): the name B-D10 (B-D8 and B-D9 exist) and E2E port 5108, accepted.

## E5

PR #190 (`test(e2e): cancel pending imports and keep the added photos`), merge commit: see git log. Independent review done; one fix round by the reviewer.

- **What landed:** I-C1 in `e2e/import.spec.ts` (`import (cancel)`, chromium, firefox, webkit; strict network guard, no exceptions) and two `AppPage` locators (`importing(count)`, `cancelImportsButton`). Nothing under `src/`, no dependency, no locale change.
- **Contract check (M5-R23):** round 1 holds the same-origin download (`/artistica/apple-touch-icon.png`) and round 2 fails the GET of `/artistica/og-image.png` so the no-cors HEAD probe runs, then holds the HEAD. Each Cancel must make the held request fail (Playwright `requestfailed`, method and URL) within 3 s, below `PROBE_TIMEOUT_MS` (8 s) and `FETCH_TIMEOUT_MS` (30 s), so only the import's abort signal can cause it. The test also checks the "Stopped adding photos." status, that the Cancel button is gone, that both photos stay in order, and that no alert appears.
- **Reviewer fixes:** (1) after each Cancel, the test checks that focus moves to the dropzone's "Upload" button. The Cancel button unmounts when it is pressed, and without that move focus would fall to `<body>` (WCAG 2.4.3). (2) The `hold()` doc comment said the helper never answers the request. The caller's route handler is what leaves it unanswered, so the comment now says that.
- **Ruling (deviation 1, two rounds):** accepted. When Cancel aborts a held download, the error is an `AbortError`, so `fetchImageBlob` sets the probe to `skipped` (`src/features/images/url.ts`, catch around the download fetch). A single held response can't show both aborts, so the plan's one-response wording can't be met. Two rounds cover both M5-R23 clauses.
- **Ruling (deviation 2, port):** accepted. The task brief's port (5109; the reviewer used 5209) replaces the plan's 7505 so that parallel worktrees don't clash. It is not committed anywhere.
- **Ruling (deviation 3, "paste a link"):** accepted. In the app, a link is added through the link field (`submitLink`). Pasting text only shows the "no image on the clipboard" message (I8). The plan's "paste" means typing or pasting the link into that field.
- **Mutations (reviewer, all caught at the expected assertion, chromium + webkit):** R1 `cancelImports` returns at once, caught at the GET `requestfailed` poll. R2 the probe's `fetch` gets only the timeout signal while its promise still races the import's signal, caught at the HEAD poll (the request itself must be aborted, not just the promise). R3 the download `fetch` gets no signal, caught at the GET poll. R4 Cancel never sets the stopped flag, caught at "Stopped adding photos.". R5 Cancel doesn't move focus, caught by the new focus check. The implementer's M1–M6 table is in the PR body.
- **Checks (reviewer, on the branch):** lint, format:check, typecheck, test:coverage (3493), test:perf (16) and build all pass. `e2e/import.spec.ts` passes on chromium, firefox and webkit (45 passed, 15 skipped by project). I-C1 passed `--repeat-each=3` on all three browsers after the fixes. Phone projects not run: the test is desktop-only by design (`runOnly`), and the owner's phone checklist keeps its Cancel item.
- **Privacy / determinism:** both URLs are build files served by the preview server, and no photo-derived data leaves the page. The test touches no output. No questions raised.
