Each Cancel must make the held request fail (Playwright `requestfailed`, method and URL) within 3 s, below `PROBE_TIMEOUT_MS` (8 s) and `FETCH_TIMEOUT_MS` (30 s), so only the import's abort signal can cause it. The Cancel button unmounts when it is pressed, and without that move focus would fall to `<body>` (WCAG 2.4.3). (2) The `hold()` doc comment said the helper never answers the request. The caller's route handler is what leaves it unanswered, so the comment now says that.
- **Ruling (deviation 1, two rounds):** accepted. When Cancel aborts a held download, the error is an `AbortError`, so `fetchImageBlob` sets the probe to `skipped` (`src/features/images/url.ts`, catch around the download fetch). A single held response can't show both aborts, so the plan's one-response wording can't be met. Two rounds cover both M5-R23 clauses.
- **Ruling (deviation 2, port):** accepted. The task brief's port (5109; the reviewer used 5209) replaces the plan's 7505 so that parallel worktrees don't clash. It is not committed anywhere.
- **Ruling (deviation 3, "paste a link"):** accepted. In the app, a link is added through the link field (`submitLink`). Pasting text only shows the "no image on the clipboard" message (I8). The plan's "paste" means typing or pasting the link into that field.
- **Mutations (reviewer, all caught at the expected assertion, chromium + webkit):** R1 `cancelImports` returns at once, caught at the GET `requestfailed` poll. R2 the probe's `fetch` gets only the timeout signal while its promise still races the import's signal, caught at the HEAD poll (the request itself must be aborted, not just the promise). R3 the download `fetch` gets no signal, caught at the GET poll. R4 Cancel never sets the stopped flag, caught at "Stopped adding photos.". R5 Cancel doesn't move focus, caught by the new focus check.
