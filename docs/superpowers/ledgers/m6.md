PR #193 (`test/i18n-locale-check`), merge commit: see git log. Independent review, one fix round by the reviewer.

- **Verified:** lint, format:check, typecheck, `i18n:check` (0 languages besides English, 0 problems), test:coverage, test:perf, build, E2E chromium and webkit on port 5203. All ten `LocaleProblem.kind`s have a fixture with an exact problem list; the real repo passes; `translated-from.json` is outside the resource globs (`locales/*/*.json`), so it does not ship; `package.json` gains only the two scripts. A scratch copy with ja copied from English and stamped, then one English value changed and `images:list.count_*` broken, exits 1 with `stale`, `plural-extra` for every English `_one` and `variables`.
- **Fixes (reviewer):** three behaviours had no test and survived a mutation; each now has one: a plural form compared with the English form of the same category (not only `_other`), `stamp` dropping entries of English strings that no longer exist, and `stale` on an English plural form.
- **Mutations (reviewer, 18 on `check-locales.ts`, all killed after the fixes):** hash 7 characters; `_zero` rejected; every form may drop `count`; variable format ignored; whitespace inside `{{ }}` significant; whitespace-only value accepted; tag check removed; letterless values warned; `SAME_AS_ENGLISH` ignored; landing folder not read; `stamp` with keys drops the rest; `stamp` keeps removed keys; plural base not matched in `stamp`; form compared only with English `_other`; `stale` skips plural forms; `missing-file` removed; `extra-file` removed; a plain key under an English plural not reported. On `locales.test.ts`: an `fr` folder and a `pt-BR` folder with one namespace each fail.
- Ruling: deviation 1 (`stamp(en, lang, keys?, previous = {})`) accepted; "keeps the rest" needs the existing stamps, and the contract's three-argument calls still work. Recorded in the overview's Ruled section.
- Ruling: deviation 2 (named tags) accepted. The repo's two `<Trans>` strings use `<name/>`, and the check compares any `<x>`, `</x>` or `<x/>` as a multiset, which covers numbered tags too.
- Ruling: deviation 3 (landing locales as a `landing` namespace, stamps under `landing:<key>`, `missing-file` when a language has one side only) accepted. Each B task owns both its app folder and its landing file, so a language never legitimately has one without the other.

- Ruling: deviation 5 accepted: `SAME_AS_ENGLISH` holds full keys (`ns:key`), so each untranslated occurrence is reviewed once; values with no letter never warn.
- Ruling: deviations 6 (stamp keys are full English keys; `i18n:stamp` accepts a plural base) and 7 (`--root <dir>`) accepted.
- Note for B1–B7: English `images:list.removeAll.confirmBody` has only `_other` (the dialog needs at least two images), so pt-BR, it and es need `_one`, `_many` and `_other` for it, each with `{{count}}`. The check does not validate English's own plural forms.
- Note: `lines:applyAll.hint`, `studies:applyAll.hint` and `presets:apply.confirmBody` use `_one` for a different message (no count) than `_other`. ja, ko and zh-CN have only `_other`, so at a count of 1 they would show the "all {{count}}" message; see Q-A4-1.

## Questions (accepted under the delegation; owner may override at 1.0)

See the overview's questions (Q1–Q17). Further questions raised during execution are added here with their default.

- **Q-A4-1 (A4 review): plural keys that hold two different messages.** `lines:applyAll.hint`, `studies:applyAll.hint` and `presets:apply.confirmBody` say one thing in `_one` ("Add another photo…", "…of your photo") and another in `_other` ("…all {{count}} images"). Languages with only `other` (ja, ko, zh-CN) cannot say the `_one` message, and the locale check rightly requires `{{count}}` in their `_other`. **Default (accepted):** before the string freeze, split each into a plain key for the single case, chosen in code by `count === 1`, and a count plural for the rest; done by whichever task still owns English strings (A3 if open, else D3 under M6-R13). The check stays strict.
