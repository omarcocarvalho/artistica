## E4

PR #191 (`fix/arrange-ghost-clip`), squash-merged; merge commit: see git log. Independent review, no fix round needed.

- **Contract:** the drag ghost is portalled to `document.body`, `position: fixed` in viewport pixels (from the hit sheet's client rect, recomputed on every move and scroll), `z-index: var(--z-popover)` (above panels and the top bar, below toasts and dialogs), `aria-hidden`, `pointer-events: none`; it goes on pointer up, Escape, `pointercancel` and unmount mid-drag. The swap target stays on the sheet in sheet pixels. The drag path is otherwise unchanged (no layout call or redraw during a drag, M5-R19 test green); no renderer, string, dependency, storage or network change. `base.css`'s `body > *` (`position: relative; z-index: 1`) is in the base layer, so the components-layer rule wins (E2E reads the computed values).
- **Accessibility:** the ghost was and stays decorative (`aria-hidden`); the refusal is still announced once on release (B-D10 asserts the live region). Forced-colours rules still match the ghost outside the layer. On the phone the preview is not inside a dialog, so no modal layer sits above `--z-popover` during a drag.
- **Checks (reviewer, own worktree):** lint, format:check, typecheck, test:coverage (3499 passed, 98.63 % statements), test:perf (16), build: green. E2E port 5208, `arrange.spec.ts` + `arrange-phone.spec.ts` on chromium, firefox, webkit, mobile-chromium, mobile-webkit: 49 passed, 46 skipped by project.
- **Reviewer mutations:** unit — portal into `body.firstElementChild` (R1), swap target in viewport pixels (R2), move ghost in sheet pixels (R3), resize ghost in sheet pixels (R4), `z-index: var(--z-panel)` (R5), `--on-paper-*` only on the layer (R6), no `aria-hidden` (R7), viewport origin off by 1 px (R8): all killed. E2E (B-D10, chromium + webkit) — ghost rendered inline in the layer, with fixed positioning and viewport pixels kept: killed, but only by the "not inside `main#main`" count; `position: absolute; z-index: 5` with the portal kept: survives the E2E, killed by `arrange-css.test.ts`.
- Ruling: the mutation results show that in today's DOM `position: fixed` alone already escapes the scroller's overflow clip (no transformed or `contain` ancestor), so the portal is defence against a future transform, containment or stacking context on the preview path. It is pinned by the unit tests (parent is `body`) and by B-D10's containment count; `fixed` over `absolute` is pinned only by the CSS test, since the window does not scroll. Accepted as sufficient.
- Ruling (deviation 1): portal target `document.body`, accepted. No preview overlay root exists; `body` is where the Radix overlays already portal.
- Ruling (deviation 2): the E2E drags past the left edge, not the bottom, accepted. Verified: the desktop shell is `h-dvh` (`src/app/App.tsx:28`) with `main#main` reaching the viewport's bottom, so a ghost past the bottom edge can never be fully in the viewport; the left corners checked by `elementFromPoint` are the ones outside the scroller.
- Ruling (deviation 3): hit-testing switched on for the single `elementFromPoint` call, with computed `pointer-events: none` asserted separately, accepted; it is the only way to satisfy both plan assertions.
- Ruling (deviations 4, 5): the name B-D10 (B-D8 and B-D9 exist) and E2E port 5108, accepted.
- No contract change, no new question.
