## Rulings

- **Ruling (A1):** malformed stored values never coerce. ±Infinity, numeric strings, booleans and arrays fall back to that field's default (as `sanitizeStudy`). B2's types-only schema relies on this.
- **Ruling (A1):** colour is exactly `#rrggbb` (trimmed, lowercased). 3-digit hex and named colours fall back to `#e0457b`, so `ColourField` emits `#rrggbb` only.
- **Ruling (B3):** duplicate rank is lexicographic over (printed studies, then `linesKey`), then input order. The plan's concatenated `${studies}|${linesKey}` broke M2 numbering (`,` sorts before `|`, which moves a prefix twin). Overview Layout contract updated in #106.
- **Ruling (B1):** `clear()` keeps `appliedLines`, as it keeps `appliedStudy`. `LineDefaultsEffect` reacts only to a change to a non-null value.
- **Ruling (B2):** a setter whose value equals the stored one does not call `set`. Returning the same state from an updater still makes `persist` write.
- **Ruling (C2, #113):** PDF line opacity uses `setExtGState` with names `GS0`, `GS1`, … per page, one per distinct opacity below 100%, in order of first use. This supersedes the plan's `newExtGState` with seeded names (plans corrected).
- **Ruling (width):** halfway values (for example 0.325 mm) snap whichever way the float falls. Deterministic; the slider only emits whole steps.

**Testing lessons:** desktop WebKit on macOS is not proof for CI, so gate on the CI webkit job. After a version change, wait for a settled preview before clicking a tile. Radix radios select only if the arrow key is still down when roving focus moves, so Playwright uses `press('ArrowRight', { delay: 50 })` on every `SegmentedControl`. After merging two PRs that touch a shared E2E helper, check it for silently dropped methods. During a GitHub outage an empty PR or check lookup means "unknown", not "none".

## Final review (task F)

1. **Geometry, rendering and PDF:** no code findings. Hand derivations match (thirds, golden, grid, armature, centre dash, the spiral arc by arc, `frameToPage`, one tile's PDF operators, the preview call list). Preview and PDF agree within 1e-6 mm across 5 setups (A4, bleed, no marks, Letter landscape, custom 1000 × 1400 mm; rotations, flips, groups, turns). No-lines PDFs are byte-identical between v0.2.0 and master (5 setups); image and `Do` names are identical with lines on and off. Edge cases (tiles from 1 × 1 to 300 × 3000 mm, 2 mm width, 10% opacity) pass. 60 mutations: 59 killed, 1 equivalent.
2. **State, pipeline and memory:** no blocker. Lines add no canvases, bitmaps, decodes or worker messages; the image XObjects are the same; CI memory is within noise of no lines. 41 mutants: 2 survived (the second finding below), 2 equivalent, the rest killed. Fixed in #118: an uncommitted Columns, Rows or colour draft followed the selection to another image (the fields are now keyed by image id); studies and lines defaults independence is pinned in both directions; `applyStudyToAll` and `applyLinesToAll` return 0 while a photo is importing (Q9 and M2-2 enforced in the store, not only by the disabled button).
3. **UI and accessibility:** axe 0 violations in every state (desktop chromium and webkit, phone mobile-chromium and mobile-webkit, light and dark); forced colors OK; screen-reader text OK ("Lines, 2 on"; page list via `Intl.ListFormat`; one live region). 30/30 mutations killed. Fixed in #118: WebKit leaves `<input type=color>` out of the Tab order (even with `tabindex=0` or Alt+Tab), so the hex beside the swatch is now an editable, labelled text input that accepts six hex digits and commits on Enter or blur (owner question PQ1). Accepted visual differences from the mockup: serif section headings, solid inset dividers, no tab icons (app-wide conventions), the raised selected corner, the taller phone Lines card.

**Memory (M3, CI, master `f5e624b`, 22 × 24 MP photos × 3 versions, every line on, MB):** start 456, import 1013, studies 1296, settled 1158, export 1292. Budgets: 1500 / 1500 / 1700. 66/66 tiles carry lines.

## Deferred (with reason)

- **Up/Down arrows on `SegmentedControl`:** the ARIA radio pattern moves on all four arrows; ours is horizontal only. App-wide since M1 → M5 accessibility polish (owner question PQ2).
- **Slider value number formatting:** locale formatting of the readout → M6 (i18n).
- **`aria-label` on role-less spans in the image list** (M1/M2, axe "incomplete") → M5.
- **`ds-badge` loses its pill in forced colors** (app-wide) → shared-UI follow-up.
- **Double announcement** when focus is in the Lines controls as an import starts (focus moves to the hint). Rare, and the same on desktop.
- **Count field during an import start:** a value typed as an import starts is committed on blur (selected image only).
- **PDF inspector limits:** a clip is reported in the user space it was written in (no CTM, no nested intersection); dash phase isn't parsed. The composer never needs them.
- **Dropped:** `setUnit`, `setTheme`, `setLanguage` and `setPageSetup` write storage on equal values (pre-M3, user actions only).

Not answered yet. Nothing was changed for them.
