## D3

PR #161 (`fix/images-intake-bounds`), squash-merged to master as the PR's own merge commit. Review: correct against M5-R23 and the `cancelImports()` contract. The download slot is held until a decode slot is free (no lock cycle: decode never waits on a download), aborted waiters leave both queues at once, the probe listens to the import's signal and its own timeout, and cancelled batches resolve to `null` without lowering a later batch's count. Cancel has a visible label contained in its accessible name (WCAG 2.5.3), sits outside the `role="status"` region, and focus moves to Upload. No new network request and nothing persisted. Lint, format, typecheck, `test:coverage` (2568), `test:perf`, build, and E2E import/focus/a11y on chromium, webkit, mobile-chromium and mobile-webkit all green.

Reviewer mutations: 12 of my own, beside the author's 16. Four survived and got tests: a decode waiter that ignores the signal, for a file (R2) and for a fetched link (R1): both now resolve their batch at once, before the decodes in flight end. A `cancelImports()` with nothing importing that still writes state (R5): the test now asserts the state object is unchanged. A probe timer that is never cleared (R9): the test now asserts no timer is left. One equivalent mutant left alone: dropping `importing === 0` from the stopped notice, since the notice is already cleared during render when an import starts. Docstring on the store's `run` now names `cancelImports()` too.

Ruling: the probe timeout uses a cleared `setTimeout` rather than `AbortSignal.timeout`. Accepted: same behaviour, and the timer is now pinned as cleared.
Ruling: `ImageList.tsx` outside D3's file map. Accepted: the Remove all step needs it, and the change is limited to the button condition.
Ruling: no E2E for Cancel. Accepted: unit tests cover the announcement, focus and placement, and the overview's phone checklist covers it on a device.
Ruling: on phones with no photo loaded, Remove all can't show (`MobileFlow` shows the empty state). Accepted: the dropzone's Cancel does the same job there.
Ruling: `createLimiter` returning `{ run, acquire }` is internal (only `store.ts` calls it), so it isn't a contract change.
