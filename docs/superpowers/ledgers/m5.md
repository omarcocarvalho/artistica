## C2

PR #159 (`fix/a11y-announcements`), squash-merged to `master` with that title. Reviewed independently, rebased onto the ledger commit.

- **Scope:** "Updating layout…" only after `UPDATING_ANNOUNCE_DELAY_MS` (500 ms) of computing, then "Layout updated." (M5-R24, `use-delayed-flag.ts`, `aria-busy` immediate); image-list details as `aria-hidden` short text plus a `VisuallyHidden` expansion; a full-width static striped fill for the indeterminate `ProgressBar` under reduced motion (M5-R25); live `Callout` and error toasts mount their region empty and fill it on the next commit; the selected-tab squiggle as a CSS `mask` over `--color-accent`, `Highlight` in forced colours.
- **Checks (reviewer):** lint, format:check, typecheck, test:coverage (166 files, 2569 tests), test:perf (16), build green. E2E chromium full (145 passed, 31 skipped; 3 flaky with "browser has been closed" under a machine load average of 20, then `a11y.spec.ts` clean twice over, 38/38); webkit and firefox on `a11y`, `import`, `app-shell`: 57 passed.
- **Mutations (reviewer, 10):** killed: "Layout updated." without a slow run, `aria-busy` on the delayed flag, the low-DPI short text spoken. Survived, then killed by two new tests in `basics.test.tsx`: the motion-preference listener never subscribed or never removed (no test changed the preference while mounted), and the squiggle `mask` dropped (the token check passed with a solid bar). Equivalent: `transition: none` dropped from the static fill (its width never changes), and info toasts deferred too (they sit inside the persistent `status` wrapper).
- **No product questions and no contract changes.**
- Ruling (C2, spoken copy): the existing `images.json` strings ("4032 by 3024 pixels", "3 copies", "Low resolution: 203 DPI") are kept. The plan's wording was an example. These strings keep the DPI value that the visible text now hides from screen readers, and `images.json` belongs to D3 in wave 1.
- Ruling (C2, live-region mechanism): accepted as an interim fix. The content arrives one React commit after the region, through a passive effect, instead of a persistent wrapper; a persistent `role="alert"` wrapper would add an empty alert to every page and change the E2E alert counts. That second commit is a separate task but not guaranteed a separate rendering update, so Chrome and WebKit may still see the region and its text in one accessibility-tree update. Deferring past two animation frames would guarantee a separate update. It breaks 20 synchronous unit tests in 6 files (measured) and would race other wave-1 PRs that add such tests, so it is not done here. **C3's 4.1.3 log and VoiceOver pass must check a status `Callout` (the gutter note) and an error toast.** If either is silent, C3 switches the deferral to two animation frames and moves those tests to `findBy`.
- Ruling (C2, E2E): no E2E waited on "Updating layout…" (`git grep` in `e2e` finds nothing); they wait on `aria-busy`, so none changed. Ruling (C2, test files): the `ProgressBar` and `Callout` cases live in `basics.test.tsx`, where those components are already tested; the port deviation is moot.
- **M5-R24 note:** the pipeline keeps `status` at `computing` across reschedules, so a continuous drag longer than 500 ms announces "Updating layout…" once and "Layout updated." at the end. That matches the rule (computing for 500 ms).
