## D2

PR #157 (`fix/studies-worker-timeout`), merged as the squash commit of #157. Reviewed and mutation-tested by an independent reviewer; `STUDY_JOB_TIMEOUT_MS = 20_000` in `study-client.ts` rejects with name `StudyTimeout` (M5-R22).

- Review: correct against M5-R22. The timer runs from the job's start, worker start-up included; a timed-out worker is terminated and the next job gets a fresh one; the second timeout in a row moves to the main thread for the session; main-thread jobs are not timed; the provider puts a timed-out job back at the front and `running` clears either way, so `pending()` reaches 0 and `aria-busy` clears. Export is untouched (the PDF path imports neither file). No new dependency, no UI string, no persisted state, no network: privacy and accessibility unaffected. Deterministic: the main-thread fallback uses the same canvas type as the worker where it can (M2-R11, unchanged).
- Measured slowest preview tile: 843 ms (4 MP, blur 7.5 % + values) at a 4× CPU throttle in Chromium, so 20 s is about 24× it (the plan estimated 15×).
- Fixes by the reviewer: two mutants survived the PR's tests, both generation guards for an abandoned worker. Added `an abandoned worker whose start-up finishes late is never given the job` (kills removing the `gen !== generation` check after `choose()`) and `a late answer from an abandoned worker does not reset the count` (kills dropping `gen === generation` from the reset). Dropped the `engine !== main` part of the reset as an equivalent mutant: nothing times a job once the main thread is chosen.
- Mutations run by the reviewer: 11; 9 killed by the PR's tests, 2 killed only after the added tests, 1 equivalent (removed). Killed examples: timeout clone not closed; abandoned worker not disposed; late init failure switching to main; timer 5 s late; timeout retries sharing the restart flag; discarding the stale-key check.
- Checks: lint, format:check, typecheck, test:coverage (2558 passed, gate green), test:perf, build; E2E `studies.spec.ts` and `studies-imports.spec.ts` on chromium and webkit (4 chromium flakes under host load average 21–27 passed on retry, and passed with `--retries=0` on a rerun).
- Ruling D2-1: "a second timeout of the same job" is implemented as "a second timeout in a row". Accepted: the renderer cannot identify jobs, preview concurrency is 1 and a timed-out job goes back to the front, so the retry is the next job unless it stopped being wanted; two different jobs stalling back to back on two fresh workers is the same evidence of a stalled engine, and a success in between resets the count. The first timeout never falls back (review focus 2).
- Ruling D2-2: the provider retries a timed-out job twice (fresh worker, then main thread) instead of once. Accepted: M5-R22 moves the preview to the main thread, it does not drop the tile; a third timeout cannot happen because main-thread jobs are untimed.
- Ruling D2-3: E2E port 4705 instead of 6802, and no new E2E test. Accepted: the plan asks for unit tests only; a 20 s worker stall is not reproducible in a browser test without a test-only hook.
- Ruling D2-4: "export is unaffected" is shown by the import graph (only `src/app/study-provider.ts` and the studies barrel import these files) rather than a test. Accepted: the plan says "no change" for export.
