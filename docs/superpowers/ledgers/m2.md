## Rulings

- **Ruling (A5, perf):** spec §3's 200 ms preview update is the product gate (D4 E2E). The overview's per-megapixel node figure is a technical target. Measured worst case after #99: about 80 ms/MP at 7.5% blur (exact small-σ Gaussian), 50–56 ms at 40–100%; CI bound 300 ms.
- **Ruling (B5, bundle):** the studies maths ships in the main chunk because `renderTile` (used by the preview) applies studies. +1.9 KB gzip, accepted. Initial JS after D2: 173.8 of 250 KB. pdf-lib stays in the PDF worker chunk.
- **Ruling (B2):** persisted study defaults — the Zod schema checks types only; `sanitizeStudy` owns every range (clamp/round blur and count, wrap hue). Load and `setStudyDefaults` give identical values.
- **Ruling (B4):** a stale placement (tile count ≠ version count) is skipped like a missing image; the next pipeline run replaces it.
- **Ruling (C2):** "C2 dispose and singleton reset" in the overview's Ruled section — one module-scope provider in `src/app/study-provider.ts`; never disposed from React effects.
- **Ruling (C1):** M2-R16 "in-flight job finishes" means a job already rendering in the worker; a job still cropping goes back to the front of the queue.
- **Ruling (#99):** M2-R18 — below σ = √(44/3) ≈ 3.83 the blur is an exact, variance-fitted Gaussian; above it the three-box path; no-op floor 1/16 px.
- **Ruling (A2):** `maxChroma` returns a boundary chroma (in gamut, `C + 1e-5` is not), not necessarily the largest where the in-gamut set along (L, h) isn't one interval. Harmless for the ramp (verified for every whole-degree hue and every ramp L).

## Deferred (with reason)

- **Silent worker stall** (a worker killed with no `error` event leaves the preview queue busy; no job timeout): export is unaffected, iOS usually kills the whole tab, and a timeout risks a false fallback on slow phones. M5.
- **Phone memory grows with the number of mounted pages** (every page's canvases and wanted study tiles stay alive; M1 design): want study tiles only for pages near the viewport. M5 "mobile memory", unless the owner's real-phone run fails.
- **Preview memory bound:** wanted + stale slot images (≤ wanted) + 32 MB retained + one in-flight job — about twice the overview's "Preview, study tiles" row. Visible through `stats().staleBytes`.
- **M2-R15 exception:** a blur/values/hue change on one of two identical photos re-runs layout (duplicates are numbered by what they print). Performance only.
- **Shared `Chip` plain variant:** add with the first radio-style chip (crop shape). M3/M5.
- **Forced-colors leftovers:** the checked segmented item keeps its accent underline; Firefox `::-moz-range-*` rules untested (forced colors are emulated in chromium only).
- **Plan-label shortcodes in code comments** (`M2-R5`, `Q11`, `D-CR2`, …; repo convention since M1): owner to decide; if removed, one `refactor:` sweep in M5.
- **`value-ramp.png` pinned to Node zlib bytes:** a Node/zlib change would fail loudly; regenerate with `--only=value-ramp`, or compare decoded pixels.
- **Duplicates with the same studies but different edits** still depend on input order (since M1, #66); fixing it changes v0.1.0 layouts. Owner question (HANDOVER Q6).
